# Frozen contracts (M1)

These files are the shared contracts. **Only the integrator edits them.** A subagent that needs a
change writes a proposal in its report (what, why, which callers) and keeps working against the
current shape until the change is approved.

| Contract | Source of truth | Consumers |
|---|---|---|
| Rust ↔ TS data types | `src-tauri/src/model/*.rs` → generated `src/bindings.ts` | everything |
| IPC commands + events | `src-tauri/src/commands/mod.rs`, `src-tauri/src/lib.rs` (`specta_builder`) | `src/ui/app/ipc.ts` |
| IPC error shape | `src-tauri/src/error.rs` (`AppError`, `ErrorKind`) | UI error rows |
| Rules-core types | `src/core/model.ts` (`Finding`, `Evidence`, `Check`, `CrashPattern`, `JarIndex`, `VersionApi`) | `src/core/**`, UI |
| Path scoping | `src-tauri/src/guard/mod.rs` (`PathGuard`) | every Rust module that touches the filesystem |
| Jar id ↔ path | `src-tauri/src/jar_id.rs` | scanner, fix engine |
| App directories | `src-tauri/src/paths.rs` (icon cache, backups, API cache) | modrinth, fix |
| Test infrastructure | `src-tauri/src/test_support/mod.rs` (`JarBuilder`) | Rust tests |
| Design tokens and rules | `DESIGN.md`, `src/styles/tokens.css`, `src/styles/tailwind.css` | UI, reviewers |
| Dependencies | `src-tauri/Cargo.toml`, `package.json` | everyone (integrator adds crates) |
| Gates | `src/core/__tests__/purity.test.ts`, `src/ui/__tests__/design-lint.test.ts` | CI |

`src/bindings.ts` is generated by `cargo test --lib export_bindings` (also `npm run bindings`, and
every debug run of the app). Never edit it by hand. CI fails if regenerating it produces a diff.

## Invariants every agent must respect

1. **Rust owns all I/O.** The webview has no fs, dialog, store, shell or http permission.
   - Commands take ids and relative, `/`-separated paths, never absolute paths from the UI.
   - A relative path is joined with `PathGuard::join_relative`, then checked with
     `check_existing` or `check_new`.
   - Scope-bearing settings (manual folders, launcher roots) change only through the native-picker
     commands. `set_settings` takes a `SettingsPatch` that cannot express them.
   - Drag-and-drop is handled in Rust (`WindowEvent::DragDrop`) and reported to the UI as
     `InstanceAdded` or `DropRejected` events.
2. **Symlinks.** Discovery registers as PathGuard roots the instance root plus the canonical
   targets of its `mods/`, `logs/` and `crash-reports/` (one level). Everything else that resolves
   outside the roots is `OutsideScope`.
3. **`src/core` is pure.** No DOM, no Node, no `@tauri-apps/*`, only `import type` from
   `../bindings`, and no `any`. This is enforced by `purity.test.ts` and `tsc -p src/core`, which
   runs without DOM or Node libs.
4. **Rust extracts, TS interprets.** Version ranges cross the boundary as
   `RawRange { syntax, raw, unrepresentable }`, in OR-of-AND form. Rust may restructure Quilt
   objects into that form but never evaluates a range. Pack identity (including inference from the
   jar majority) lives in `src/core/pack`, so `src/core` chooses the Modrinth version for
   replace/install and passes a `versionId`.
   Range semantics are settled in `src/core/version`, so checks must not handle these cases
   again:
   - A bare Maven version (`47.1.0`) is a *soft* requirement and matches everything, as in FML.
   - In Fabric ranges only the tested version is MC-normalised. Predicate versions stay as written,
     as in fabric-loader, so `>=1.20.5-pre1` does not match game `1.20.5-pre1`.
   - `satisfies` returns `null` (unknown, never a guess) for unparseable or unrepresentable input.
   - `Instance.loader = null` together with `metadataSource: 'launcher'` means a **vanilla**
     instance. `LoaderKind` has no vanilla member.
5. **IDs.**
   - Instance id = first 16 hex chars of SHA-1 over the canonical game dir path, lowercased on
     Windows and macOS. Discovery de-duplicates by it.
   - Top-level jar id = its path relative to the scan root with `/` separators and any
     `.disabled` suffix **stripped**, so it survives enable/disable: `mods/x.jar` for both
     `x.jar` and `x.jar.disabled`, or `client-overrides/mods/y.jar` in a `.mrpack`. If both
     `x.jar` and `x.jar.disabled` exist, the disabled one is `mods/x.jar#disabled`.
     `JarRecord.path` holds the actual file path. Build ids and resolve them back to files only
     with `src-tauri/src/jar_id.rs`.
   - Nested jar id = `<parentId>!/<entry path>`.
   - Log source id = its path relative to the game dir. Only ids that `list_log_sources` returned
     are accepted.
   - Backup id = `<instanceId>/<ms>`, validated as `^[0-9a-f]{16}/[0-9]+$`.
6. **Numbers.** Values that are `u64` in Rust are exported as TS `number` via
   `#[specta(type = specta_typescript::Number)]`, never `f64` (which exports as `number | null`).
   They are byte sizes and epoch milliseconds, always below 2^53.
7. **Errors.** Commands return `Result<T, AppError>`. `AppError.message` is a complete sentence a
   user can act on. No `unwrap()`/`expect()` outside `#[cfg(test)]`.
8. **Fixes.**
   - The UI sends `FixAction` intents only. `plan_work_order` returns a stored `WorkOrder`, and
     `execute_work_order(id)` runs only stored orders.
   - Rust re-fetches every `versionId` from the API and re-validates it against the
     `PackIdentity` sent with `plan_work_order`. That identity must itself agree with launcher or
     mrpack metadata and any override. The checks:
     - `version.loaders` contains the pack loader (NeoForge 1.20.1 also accepts `forge`).
     - `version.gameVersions` contains the pack MC version.
     - `Replace` stays within the same Modrinth project as the current jar, which must be
       identifiable by hash.
     - After download, the new jar must declare the expected mod id.

     Any failure rejects the order with a readable error naming the action.
   - Downloadable files exclude `fileType` `sources-jar`, `dev-jar`, `javadoc-jar` and `signature`.
     From what remains, pick the file marked `primary`, else the sole file, else planning fails
     with a readable error.
   - The URL must be `https://cdn.modrinth.com/…` exactly as the API returned it.
   - Every download is SHA-512-verified and written as temp file in the same dir → fsync → rename.
   - "Remove" moves the file into the backup snapshot; nothing is ever deleted.
   - Every order is refused while `game_running` reports true.
   - Undo is per action (`plan_undo(backupId, actionIndexes)`). It runs as a work order
     (`kind: undo`) and verifies hashes before it overwrites anything. Enter confirms only a
     single-rename undo; everything else needs Execute.
   - Update suggestions: `["release"]` unless `includeBeta`. If no release is compatible,
     `src/core` retries with `["release","beta"]` and labels any result "beta". Alpha versions are
     never suggested.
9. **Minecraft versions** are no longer only `1.x.y`. Year-based releases such as `26.1`, `26.1.2`
   and `26.3`, and snapshots such as `26.4-snapshot-6`, are live, alongside legacy `1.21.11`,
   `23w51a` and `1.20.5-pre1`. Version code must never assume a `1.` prefix; use
   `VersionSubject = 'minecraft'`.
10. **Network.** The only hosts are `api.modrinth.com` (API) and `cdn.modrinth.com` (downloads
    and icons). Every request sends the User-Agent
    `KingCreeper531/modpack-doctor/<version> (github.com/KingCreeper531/modpack-doctor)`.
    Every static check works with no network.
11. **Crash detection vs classification.** `src/core/crash/anchors.ts` is the single anchor
    list. It goes to both `set_watch` and `read_log_digest`.
    - Rust watch mode detects only. It tails `latest.log` against the anchors (surviving log
      rotation), and watches for a new `crash-reports/*.txt` or `hs_err_pid*.log`.
    - The instance's Java process exiting is also a trigger. Process detection is shared with the
      running-game guard (`src-tauri/src/process/`, built in M4, reused by M6).
    - Triggers are debounced into one `CrashDetected` per crash episode (rules in
      `model/logs.rs`). A normal quit, meaning a process exit with no anchor hit and no new crash
      file, emits nothing.
    - The UI classifies the episode's `source` with `src/core` and sends a native notification
      only for an error-severity crash finding.
    - Rust never starts watchers by itself. The UI re-arms `Settings.watched` at startup.
    - Required test: a load-time failure that appears **only** in `latest.log` (no crash report),
      followed by process exit, must produce exactly one `CrashDetected`.
12. **NeoForge/Forge.**
    - `ModMeta.loader` decides per entry. A `neoforge` dependency means NeoForge; a `forge`
      dependency, or neither, means Forge.
    - `languageRange` (`loaderVersion`) is an FML/language-loader range and is never compared with
      the Forge or NeoForge version. `loaderRange` is the range of the dependency on the loader mod.
    - NeoForge 1.20.1 counts as Forge 47.x-compatible.
    - A jar that ships both `neoforge.mods.toml` and `mods.toml` yields two `ModMeta` with the
      same `modId` and different `loader`. E-DUP-ID must ignore duplicates within one jar.
13. **Known model gaps** (accepted for now; revisit when a check needs them):
    - Quilt "any of" dependency arrays become individually Optional dependencies, so a missing
      "one of A, B" is not reported.
    - `JarRecord.moduleName` comes from `module-info` or `Automatic-Module-Name` only. `src/core`
      derives the JDK automatic name from the file name when it is absent.

## Finding codes

| Code | Default severity | Meaning |
|---|---|---|
| `E-WRONG-LOADER` | error | jar targets a loader the pack doesn't run (NeoForge 1.20.1 ↔ Forge 47.x counts as compatible) |
| `E-MC-RANGE` | error | declared Minecraft range excludes the pack's MC version |
| `E-LOADER-RANGE` | error | declared loader-dependency range excludes the pack's loader version |
| `E-DEP-RANGE` | error | dependency present, but its version is outside the declared range |
| `E-MISSING-DEP` | error | required dependency absent. Built-ins (`minecraft`, `forge`, `neoforge`, `java`, `fabricloader`, `fabric`, `quilt_loader`, `javafml`, `lowcodefml`, …), `provides` and nested jars count as present |
| `E-DUP-ID` | error | two active top-level jars declare the same mod id (identical nested libraries are de-duplicated) |
| `E-SPLIT-PKG` | error | same Java package in the own classes of ≥ 2 top-level jars, on Forge/NeoForge (JPMS `ResolutionException`) |
| `I-SPLIT-PKG` | info | same, on Fabric/Quilt (no module layer) |
| `E-INCOMPAT` | error | a declared `incompatible`/`breaks` entry is present and in range |
| `W-CLIENT-ON-SERVER` | warning | client-only mod in a server instance |
| `W-CORRUPT-JAR` | warning | jar unreadable or its metadata is invalid |
| `I-NOT-ON-MODRINTH` | info | hash not found on Modrinth (possibly CurseForge or manual); never raised for `failed` lookups |
| `W-JAVA-CLASS` | warning | jar's class files need a newer Java than the pack's MC version ships with |
| `C-MIXIN` … `C-SUSPECTED` | from the log | mixin, resolution, missing mandatory deps, Fabric incompatibility, NoClassDef, OOM, Java version, suspected mods |
| `C-ROOT-CAUSE` | error | fallback when nothing specific matched: the innermost `Caused by:`, mapped to a jar when possible |
| `C-NATIVE` | error | hs_err native crash; names the problematic frame and library (e.g. a GPU driver) |
