## M2: foundations (this commit)
Seven agents worked in parallel in separate worktrees. The integrator merged every branch and ran every gate.

| Stream | Module | Result |
|---|---|---|
| A, scanner | `src-tauri/src/scan` | Parses every loader's metadata (Forge/NeoForge/Fabric/Quilt/mcmod.info). Recurses into nested jars with a zip-bomb budget. Scope is PathGuard-checked. Records the module name. 300 jars scan in about 190 ms in release with a warm OS cache. |
| B, discovery | `src-tauri/src/discovery` | Supports the Modrinth App (both app.db schemas, read-only, proven unchanged), Prism/MultiMC, CurseForge, vanilla and manual folders. Ids stay stable across first launch. |
| C, version ranges | `src/core/version` | Maven ranges compare exactly as FML does. Fabric predicates and MC normalisation (including year-based versions) follow fabric-loader. About 470 cases. |
| D, crash library + digest | `src/core/crash`, `src-tauri/src/logs` | 10 patterns and tiered watch anchors. The streaming digest is constant-memory with eviction and option clamping. |
| E, Modrinth client | `src-tauri/src/modrinth` | Batching, a 300/min limiter, 429 handling, a TTL disk cache, verified CDN downloads, and mod-id → project resolution. |
| F, design sheet | `src/ui/components`, `glyphs`, `design` | Every component and state, a canvas TileGrid (1,000 tiles), and render tests. |
| G, fixtures | `fixtures/logs` | An independent corpus of 47 cases, including traps and negative cases. |

  - 874 Vitest tests, including all 47 corpus cases, the design-lint gate with its self-test, and the purity gate.
  - Both typechecks clean.
  - A full `tauri build` producing `.msi` and `.exe`.

## M3: static checks, end to end (this commit)
Three agents worked in parallel worktrees: **H** checks (`src/core/checks`, `src/core/pack`), **I** screens
(`src/ui`), and **J** Rust wiring (`commands`, `state`, `settings`). The scanner (A) was resumed for
follow-ups. A research agent studied the loaders' source code, and an independent reviewer audited the
result.

- **Static checks:** pack identity (override > launcher/mrpack > jar majority, loader first), jar index,
  and every SPEC check: wrong loader, MC/loader/dependency ranges, missing deps, duplicate ids, split
  packages, declared incompatibilities, client-only on a server, corrupt jars, Java class version, and
  not-on-Modrinth.
- **The real app:** instance rail, summary strip, live scan grid, triage list with evidence, inspector
  with a validated pack override, virtualised mod table, empty and error states, an inspector drawer
  below 1168 px wide, and theme following. The IPC layer is real in Tauri and a mock only in dev
  browsers; the mock is excluded from production builds.
- **Rust wiring:** discovery → registry → PathGuard roots (scope changes serialised, scans hold a
  read lock), Rust-side folder/launcher-root pickers, `scan_instance` with live events and the scan
  cache, settings persisted through tauri-plugin-store with validated patches, and a readable
  `unavailable` error for later-milestone commands.
- **Real-world validation:** the M2 plan's "read-only smoke test on your instances" became a dev
  tool (`examples/smoke_scan.rs` + `SMOKE_DIR` test). On the owner's 27 instances it surfaced false
  positives in packs whose `latest.log` proves they load. Three source-code research rounds
  (`docs/research/loader-enforcement.md`) turned those into loader-accurate rules:
  - FML's `VersionSupportMatrix` on every branch;
  - FML duplicate-id resolution (newest wins);
  - which metadata file each loader version reads;
  - legacy FML 1.12 rules;
  - Sinytra Connector;
  - jars built for another loader;
  - metadata-less jars and `FMLModType`.

  Smoke result: errors went 24 → 8. Every remaining error is either confirmed (Verity is missing
  Searchables; ATM10 really has Iris and Embeddium together) or in a pack with no successful launch on
  record. Every pack known to load shows 0 errors. Discovery takes about 1 s; ATM9/ATM10 (≈420 jars)
  scan in about 1.5 s.
- **Contract changes during M3:**
  - `JarRecord.metadataErrors` (`MetadataError`): a jar is Corrupt only if no metadata file parsed.
  - `JarRecord.fmlModType`.
  - `ErrorKind::Unavailable`.
  - `discovery::locate_game_dir` made public.
  - `remove_launcher_root` may also drop a stale manual folder.
- **Gates:**
  - 228 Rust tests and clippy `-D warnings` (including examples) clean, with no bindings drift;
  - 1505 Vitest tests;
  - both typechecks clean;
  - the production build contains no mock data;
  - a full `tauri build` produces `.msi` and `.exe`.

  Screenshots are at 960×600, 1280×800 and 1920×1080 in both themes (`docs/screenshots/m3/`,
  untracked), plus real-app captures.
- **Decisions:**
  - Severities follow what each loader actually does (info/warn/error), and the UI shows a severity
    word when it differs from the code's prefix.
  - Incendium/Nullscape (`forge` and `neoforge` both optional) are accepted on Forge.
  - Split-package overlaps that involve bundled libraries are capped at info.
  - Forge never reads `neoforge.mods.toml`, even when the MC version is unknown.
- **Known gaps, documented in `src/core/checks/README.md`:**
  - legacy `@Mod` annotations;
  - `config/fml.toml` `dependencyOverrides`;
  - Connector `hiddenMods` and its runtime mixin safeguard;
  - the exact NeoForge 20.6 build that switched to FML 3.0.19.
- **Carried forward:**
  - M4: the watch episode state machine and process detection; also removing a manual instance should
    clean up its `watched` and `overrides` entries.
  - M5: a Modrinth "unreachable" notice, and a review of E's extra alias slugs against the live API.

## M4 — Crash analysis, evidence view, watch mode

- **Agents:**
  - D (crash library, `src/core/crash/**`): real-log false positives fixed (Suspected Mods, frame
    blame, session-kept-running gate). The real crash smoke over your instances' logs shows
    **0 false positives** on logs that reached the game.
  - K (Rust, `logs/{sources,tail,episode,watch}.rs`, `process/**`, `commands/logs.rs`): log sources,
    bounded digest command, tiered watch mode with the episode state machine, Java process detection
    shared with the M6 running-game guard.
  - L (UI, `src/ui/**` + `src/core/crash/summary.ts`): FINDINGS/CRASHES tabs, source list,
    Diagnosis/Log switch, virtualised log viewer, crash inspector, watch toggle, notifications with a
    denied-permission banner, mock crash scenario (`?scenario=crash`). Fixed the flaky
    override-editor test (it raced the mock's deferred settings patch).
  - Independent reviewer, then K2 (Rust) and L2 (UI) for its findings; the reviewer re-checked
    the fixes.
- **Review findings fixed:**
  - Suppression is now tied to the Java processes running at emission (5 s grace), not a quiet
    timer that dropped triggers kept alive. One crash = one notification, including an FML error
    screen left open before quitting.
  - hs_err files in the JVM's working dir (vanilla launcher runs in `.minecraft`) are picked up on
    exit and readable as `@cwd/hs_err_pid<pid>.log`.
  - `latest.log` goes through the PathGuard; only `crash-*.txt` are crash reports; a stopped
    watcher can never emit; contextual hits survive a process start.
  - UI: a race that could lose the notification; re-arm after every discovery; notification
    titled "<instance> crashed"; no alert for the instance already open; keyboard radio/tab
    patterns; log scroll no longer jumps on re-analysis; `.mrpack` has no watch toggle.
  - Mine: crash rows keep their title in narrow panes, scan grid caps at 25vh on small windows,
    the two vanilla crash-handler lines became contextual anchors (a crash report follows).
- **Known gaps (CONTRACTS invariant 11):** JVM failures that only reach stderr (wrong Java);
  hs_err in a working dir outside every guard root (CurseForge's `Install` dir) — fixing that
  means registering launcher folders as roots, which needs an owner decision.
- **Re-review:** confirmed every finding fixed (#11 deferred). Its new minor and nits are fixed
  too: a new `latest.log` lifts a suppression when no reported process is running (relaunch of
  an unmatched game), crash files stay quiet through the coalesce window after an exit-only
  emission, a working dir is recorded once sysinfo reports it, and `@cwd/` ids read as
  "launcher folder". Not done: caching the hs_err header reads in a shared `.minecraft`.
- **Contract changes during M4:** `@cwd/hs_err_pid<pid>.log` source ids (invariant 5);
  process-tied suppression, guarded tail, `crash-*.txt`, re-arm after every discovery and the
  known gaps (invariant 11). Bindings changed only in doc comments.
- **Gates:**
  - 315 Rust tests and clippy `-D warnings` (including examples) clean;
  - 1589 Vitest tests, green on repeated runs (the override-editor flake is gone);
  - both typechecks clean; the production build contains no mock data;
  - a full `tauri build` produces `.msi` (6.00 MiB) and `.exe` (4.32 MiB);
  - the real crash smoke reports 0 false positives.

  Screenshots at 960×600, 1280×800 and 1920×1080 in both themes (`docs/screenshots/m4/`,
  untracked), plus a capture of the release build on your instances.

- **Found by me in the visual / real-app loop:**

    The format is now decided by magic bytes (SVG/HTML still refused).
  - The offline notice crowded the pack's counts out of the summary strip.
  - Existing `enable` fixes now come before `installDependency` (don't download a mod you have).
- **Review findings fixed:**
  - Downgrades: Modrinth returns the newest *matching* version, which can be older than a beta

  - A rescan during a lookup could leave Modrinth stuck "looking up…" with Refresh disabled.
  - All results waited on icon downloads: icons are now a separate `modrinth_icons` pass that
    never runs when Modrinth is off or unreachable, stops when switched off mid-pass, and gives
    up after one timeout.
  - Inspector "up to date" only when known (`updateStatus`: update / up to date / no compatible
    version / unknown); "unreachable" only for network problems; rate-limit countdown visible
    at 1280×800; fast off→on toggle race; colliding icon temp files.
  - Contract decisions: Quilt accepts `fabric` versions (M6 planner too); "sole file" fails when
    no file is primary and any was dropped.
- **Real-data check:** `smoke_modrinth` + `real-modrinth-smoke.test.ts` on 23 real instances with
  live Modrinth data: **0 suspect updates** (wrong loader, wrong MC version, alpha, or not newer).
